# Stage 8：整体导航与布局重构方案

最后更新：2026-06-03

## 当前问题

系统从“学生管理系统”逐步扩展到“AI 教培工作台”后，顶部横向 tab 已经达到 11 个：

- 首页
- 班级管理
- 学员管理
- 意向学员
- 收费记录
- 考勤记录
- 成绩记录
- 沟通记录
- 统计报表
- 知识库
- AI 工作台

继续横向排列会带来几个问题：

- 模块越来越多，顶部越来越拥挤。
- 用户很难看出哪些模块属于同一个业务域。
- 移动端虽然可以横向滚动，但信息层级不清楚。
- 后续增加内容生产、资料库、题库、AI Agent 后，会更乱。

## 结论

建议改成“左侧分组导航 + 主工作区”的结构。

但不建议现在把成绩记录、沟通记录等模块真正合并进学员管理内部。更稳的做法是：

- 视觉上：成绩、沟通放到“学员”分组下面，作为二级菜单。
- 技术上：仍然保留原来的独立 tab、独立模块、独立渲染函数。

这样改动范围可控，不破坏现有业务数据和 API。

## 推荐信息架构

### 1. 工作台

- 首页：`dashboard`
- 统计报表：`reports`
- 数据体检：仍保留顶部快捷按钮，不作为主菜单页面
- 数据管理：仍保留顶部快捷按钮，不作为主菜单页面

说明：

首页是日常入口，统计报表是经营复盘入口。数据体检和数据管理属于工具，不宜和业务模块同级堆在导航里。

### 2. 教务管理

- 班级管理：`classes`
- 考勤记录：`attendance`
- 收费记录：`fees`

说明：

这三个是班级运营和教务动作，放在一起更符合日常使用路径：

```text
建班/排班 → 录考勤 → 看课消/收费
```

### 3. 学员与招生

- 学员管理：`students`
- 成绩记录：`grades`
- 沟通记录：`communications`
- 意向学员：`prospects`

说明：

成绩和沟通确实更像学员档案的子模块。短期作为二级菜单展示，长期可以逐步在学员详情页增强“成绩/沟通聚合视图”。

不建议现在直接合并原因：

- 成绩记录支持独立筛选、导入导出、批量删除。
- 沟通记录支持状态、主题、批量操作。
- 直接塞进学员管理会让学员页变重。
- 现有代码已经稳定，先做导航层整理更稳。

### 4. AI 与知识

- AI 工作台：`ai-workspace`
- 知识库：`knowledge`

说明：

这是后续增长最快的区域，应单独成组。未来可扩展：

- 内容生产
- 风格库
- 资料库
- 题库
- Agent 日志
- 草稿箱

## 移动端布局建议

移动端不要强行保留固定左侧栏。

推荐：

- 900px 以上：左侧固定导航。
- 700px 到 900px：左侧窄栏，只显示短文字或图标+短名。
- 700px 以下：顶部显示“菜单”按钮，点击展开抽屉式导航。

第一版可以简化：

- 桌面端使用左侧栏。
- 小屏端把左侧栏变成横向滚动分组导航或折叠区。
- 不急着做复杂抽屉动画。

## 顶部 Header 调整

顶部 Header 目前工具按钮较多，建议保留：

- 夜间模式
- 隐私隐藏
- 已保存状态
- 撤回上一步
- 数据体检
- 数据管理

可以弱化或折叠：

- 同步说明
- 解绑
- 导出备份
- 导入备份

建议后续做一个“更多”按钮，把低频工具收进去。

## 技术实现建议

### 不改业务模块

第一阶段不要改这些模块内部逻辑：

- `student.js`
- `grade.js`
- `communication.js`
- `fee.js`
- `attendance.js`
- `class.js`
- `knowledge.js`
- `ai-workspace.js`

只改：

- `index.html`
- `css/style.css`
- `js/data.js`
- `js/dashboard.js` 中少量跳转兼容

### 保留原 tab 机制

继续使用：

```html
data-tab="students"
id="tab-students"
```

只是把 `.tabs` 改造成 `.app-sidebar`，把 `.tab` 改造成左侧导航按钮。

这样 `switchTab('students')`、`document.querySelector('[data-tab="students"]')` 等旧代码可以继续工作。

### 新增导航结构

建议 HTML：

```html
<div class="app-shell">
  <aside class="app-sidebar">
    <div class="nav-section">
      <div class="nav-section-title">工作台</div>
      <button class="tab nav-item active" data-tab="dashboard">首页</button>
      <button class="tab nav-item" data-tab="reports">统计报表</button>
    </div>
    ...
  </aside>

  <main class="app-main">
    <div class="stat-grid" id="statGrid"></div>
    <div class="tab-content active" id="tab-dashboard"></div>
    ...
  </main>
</div>
```

### CSS 方向

核心样式：

```css
.app-shell {
  display: grid;
  grid-template-columns: 220px minmax(0, 1fr);
  gap: 16px;
  max-width: 1500px;
  margin: 0 auto;
  padding: 20px;
}

.app-sidebar {
  position: sticky;
  top: 16px;
  align-self: start;
  background: var(--bg-card);
  border-radius: 12px;
  box-shadow: 0 2px 12px var(--shadow);
  padding: 12px;
}

.app-main {
  min-width: 0;
}
```

注意：

- `.app-main { min-width: 0; }` 很重要，否则表格横向滚动可能撑破布局。
- 表格仍然依赖 `.table-wrapper { overflow-x: auto; }`。
