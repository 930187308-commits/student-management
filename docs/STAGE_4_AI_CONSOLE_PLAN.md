## 阶段 4 第二轮完成内容（2026-06-02）

**目标**：让 AI 工作台从"静态空壳"升级为"能读取现有前端数据并生成本地占位建议"的前端原型。

### A. 基础细节修复
- `index.html` `<title>` 改为 "AI 教培工作台"
- 所有 CSS 色值改为 `var(--text-primary/secondary/muted)` 等 CSS 变量，适配夜间模式

- 表单元素（select/textarea）背景色使用 `var(--input-bg)`

### B. 数据感知函数
新增 `getAIWorkspaceSummary()`，读取本地 data 计算：
- 在读学员数（status = active + pending）
- 待续费学员数（status = pending）
- 意向学员数
- 欠费记录数和欠费金额
- 本月已消课时（本月所有出勤记录）
- 近一周新增沟通记录数

### C. 业务快照区域
AI 工作台顶部新增"当前业务快照"卡片：
- 6 个指标格（3×2 布局）+ 底部近一周沟通汇总
- 数字全部来自 `getAIWorkspaceSummary()`
- 无数据时显示 0，不出现 undefined/null/NaN
- 样式与首页统计卡片一致

### D. 经营分析 Agent 本地占位增强
biz-agent 的 4 个任务类型（生成本周/月经营报告、班级课消分析、欠费预警）改为调用 `generateBizAgentContent()` 生成本地模板化内容，包含真实数据汇总（班级列表、欠费明细、课消余额等），明确标注"本地占位分析"。

### E. 学情沟通 Agent 本地占位增强
learning-agent 的 3 个任务类型改为调用 `generateLearningAgentContent()` 生成模板化占位文本，学员姓名从输入框第一行读取，不自动带出敏感数据，明确标注"本地占位模板"。

### F. 招生跟进 Agent 本地占位增强
recruit-agent 的 4 个任务类型改为调用 `generateRecruitAgentContent()` 基于 prospects 数组做简单汇总（待跟进/试课中/组班中/已成交人数），明确标注"本地占位分析"。

### G. Agent 日志优化
- 日志在点击"生成结果"时才记录，切换 Agent 不记录
- 最多保留 50 条（已有实现）
- 清空日志功能保留

### 明确说明
- **仍未接真实 AI API**，所有输出均为本地规则/模板占位
- 不录入真实数据，不改后端/SQLite/API

### 下一步建议
- 由 Codex 规划 AI API 接入方式和数据权限边界
- 建议 AI 输出存入会话日志，不改业务数据

## 第一批 AI 功能（优先级排序）

### F1：生成学生阶段反馈

**触发入口**：学员详情页 → 点"AI 生成反馈"按钮

**AI 读取的数据**：
- 该学员的成绩记录（最近 5-10 次）
- 该学员的考勤记录（最近 1 个月）
- 该学员的缴费记录（已缴课时、剩余课时）

**输出**：一段文字反馈稿

```
格式：
[学员姓名] 近期学习情况（2026年X月）

学习表现：...
主要进步：...
薄弱知识点：...
建议：...

生成时间：2026-06-01
```

**用户操作**：点"复制" → 粘贴到微信发给家长

**技术实现**：
1. 前端把学员 ID 发给后端
2. 后端调 AI API，把数据组装成 prompt
3. AI 返回文字结果
4. 前端展示，支持复制

---

### F2：生成续费沟通话术

**触发入口**：两个入口
- 首页"欠费提醒" → 点学员 → "生成话术"
- 学员详情页 → 点"AI 生成话术"

**AI 读取的数据**：
- 学员已缴课时、已消课时、剩余课时
- 学员历史续费记录
- 班级信息（当前在读班级、课程进度）

**输出**：微信话术，支持不同语气

```
【催续费话术 - 温和版】
王五妈妈您好，王五在我们班学习快两个月了，目前还剩X课时。
考虑到孩子的学习连续性，建议近期安排续费。
您看这周方便沟通一下吗？

【催续费话术 - 直接版】
王五妈妈，王五剩余课时不足，建议本周内确定续费安排。
```

**用户操作**：选一个版本 → 复制 → 发微信

### F3：生成本周经营报告

**触发入口**：首页顶部 → 点"AI 生成周报"

**AI 读取的数据**：
- 本周新增学员数量
- 本周出勤人次（各班级考勤汇总）
- 本周收费金额（已缴记录）
- 本周欠费金额
- 本周沟通记录数量
- 续费提醒列表

**输出**：一段周报文字

```
【白老师本周经营周报】
时间：2026年5月26日 - 6月1日

学员动态：
- 新增在读学员 X 名
- 本周出勤共 Y 人次
- 续费提醒：X 名学员课时不足

财务摘要：
- 本周已缴 ¥XXX
- 本周欠费 ¥XXX

下周建议：
- 重点跟进 X 名待续费学员
- 班级满班率 XX%
```

**用户操作**：复制 → 粘贴到自己保存经营数据的地方

## 统一技术方案

### AI 接口选择

**推荐：Deepseek API**（性价比最高）

- 价格便宜（比 Claude/OpenAI 便宜很多）
- 中文处理能力强
- 效果够用

**备选：Claude API**（效果最好）

- 贵一点，但输出质量更高
- 如果 Deepseek 效果不够用再换

### 前端交互设计

**每个 AI 功能都是同一个模式：**

```
点击按钮 → 显示"AI 生成中..." → 显示结果 → 复制/关闭
```

结果展示统一用现有的 modal 弹窗，不新增特殊 UI。

### 数据安全

- AI 读取的是系统已有数据，不写入新数据
- 所有 AI 输出必须经过老师确认再使用
- 不自动发送任何内容，不自动修改业务数据

### 后续扩展预留

- Agent 日志记录（每次 AI 调用写入 `agent_logs` 表）
- 批量生成（多个学员一起生成）
- 模板自定义（话术风格自己调整）

## 与现有系统对接方式

### 数据流

```
用户点击按钮
    ↓
前端调用 /api/ai/generate（POST）
    ↓
后端组装 prompt（读系统数据 + 用户指令）
    ↓
后端调用 AI API（Deepseek/Claude）
    ↓
AI 返回结果
    ↓
前端展示 modal
    ↓
用户复制使用
```

### API 设计

```
POST /api/ai/generate
Body: {
  "task": "student-feedback",
  "studentId": "s123",
  "options": {
    "tone": "normal"  // 预留：温和/直接
  }
}

Response: {
  "success": true,
  "result": "王五近期学习情况...\n主要进步...\n薄弱点..."
}
```

### 错误处理

- AI 接口超时：显示"生成失败，请重试"
- AI 返回内容异常：显示"生成结果异常，已记录"
- 网络问题：显示"网络异常，请检查连接"
